# Job ideas — not built yet

Jobs that are real chief-of-staff work but aren't in the repo yet. They're parked
here on purpose, so the job list stays short enough to hold in your head.

## The graduation rule

A job moves from this file into `jobs/` when a user has asked for it **three
times**. That rule is what keeps fourteen jobs from becoming thirty. If you keep
reaching for something parked here, that's the signal to build it.

## Parked

| Idea | What it would do | Why it's parked |
|---|---|---|
| `escalate` | The escalation ladder for non-delivery: soft check-in → written concern → pattern recap → leadership summary → formal consequence, each rung with the artifact that justifies the next | Powerful but occasional; a strong candidate when a user hits repeated non-delivery |
| `announce-a-change` | Rollout communication for an operating-model change, using the three-level cascade (leader to all, you to all, you 1:1) | Occasional; overlaps with `draft-a-message` for smaller changes |
| `launch-readiness` | Gate check before anything reaches customers: what's broken, missing, or only cosmetic | Product-specific; not every CoS owns launches |
| `handle-an-incident` | Something broke and people are watching: name an owner, hold the line publicly, keep a timeline, close it | Rare, high-pressure; adjacent to `post-mortem` |
| `hiring-support` | Job spec, scorecard, interview loop | Narrow; owned by different people at different companies |
| `vendor-and-contract-watch` | Renewal dates, obligations, what's up for review | Narrow and occasional |
| `research-brief` | Pressure-test an idea before anyone builds it | Overlaps with existing prep work |
| `stakeholder-map` | Who matters, what they want, how they relate | Useful once, rarely recurring |

## Merged, not parked

Some ideas aren't here because they're already *inside* an existing job as a mode.
For example prep-a-1:1, run-a-review and board prep are all modes of
`prepare-a-meeting`. Before proposing a new job, check whether it's a mode of one
that exists.
