# How to do it

Read the rules first. This is one method, five audiences. The facts are the same
each time; what changes is length, framing, and what you leave out. Pick the mode
(see [modes.md](modes.md)).

## Run identity

Use audience/mode + reporting period. A rerun updates the same draft. A send or
external document marked succeeded is never repeated automatically; an action
left in-progress is verified in the selected tool or escalated to the user before
retry.

## The shared method

1. **Pull the same facts every time:** project status from `projects/`, movement
   since last update, what's stuck, decisions made and decisions needed
   (`decisions/`, `registers/questions.md`), and progress against goals
   (`org/goals.md`) if goals exist.
2. **Sort into: moved · stuck · needs a decision · asks.** This spine is the same
   for every audience.
3. **Calibrate for the mode** using the audience table in `modes.md` — what this
   audience needs, what it never needs, and the tone.
4. **Draft into `reports/`.** Check every number against its source before it
   goes in.
5. **Sending is a separate yes.** The draft is yours until you approve sending
   it.

## The one rule that keeps five audiences honest

Never tell two audiences different *facts*. You change emphasis, depth and
framing — not the truth. If a risk is real for the board, it's real for the team;
you just say it differently.
