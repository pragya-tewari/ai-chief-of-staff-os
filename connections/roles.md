# Roles

Jobs and rules speak in roles, not brand names. This is what makes the system
work for a chief of staff at any company, with any stack.

| Role | What it is | Common tools |
|---|---|---|
| task tool | where work and owners live | the built-in list, Asana, Linear, Jira, ClickUp |
| chat | team messaging | Slack, Teams, Cliq |
| mail | formal communication | any email |
| docs | formal documents | Google Docs, Notion, Writer |
| sheets | numbers and trackers | any spreadsheet |
| calendar | cadence and scheduling | any calendar |
| meetings | recordings and transcripts | Zoom, Meet, Granola |

## How a role gets filled

Each tool has a maintainer-owned file in this folder (`asana.md`, `slack.md`, …)
that declares the roles and capabilities it can provide. Your private
`workspace/connections.md` says which tool fills each role and whether that
specific connection is documented, connected or verified. A job combines the
two records before the particular external action it plans.

If a role has no connected tool, the job says so and offers what it can do
without it — for tasks, that means the built-in list.
