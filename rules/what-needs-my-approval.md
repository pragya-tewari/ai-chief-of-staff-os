# What needs my approval

This is the gate. Every job checks it before writing anything.

## The line that carries it

**Recording is not telling.** Writing something into your own workspace is
mostly free. Putting something on another person's screen never is. And reading
is not automatically free when the source is sensitive.

## The table

Keyed by destination *and* action.

| Destination / action | Default | Notes |
|---|---|---|
| Reading ordinary workspace files | free | your own memory |
| Reading a connected tool | free for the relevant source, minimum fields | not blanket — see [safety.md](safety.md) |
| Reading `private/` | **ask** | people-sensitive; opened only when you say so |
| Reading mail / HR / comp / legal / medical | **ask, scoped** | name the specific thing needed, or it is off-limits |
| Writing ordinary workspace notes, projects, meetings | free | internal memory |
| Writing registers, the built-in `tasks.md`, generated `reports/` | free | ledgers and views you own |
| Writing a `decisions/` record | **ask** | a claim about what was settled |
| Writing to `private/` | **ask** | sensitive |
| Proposing an edit to the rules or your overrides | **ask** | the assistant never self-edits rules |
| Creating / updating / assigning in an external tool | **ask** | it lands on someone else's screen |
| Telling anyone about a task (chat, email) | **ask** | whichever task system is live |
| Any send, publish, or message | **ask** | always |
| **Never without an explicit instruction** | — | see the never-list below |

## The never-list

These never happen unless you explicitly instruct them, in the moment:

- Sending external email.
- Changing a task's owner.
- Editing financial figures.
- Deleting or archiving anything.
- Bulk-creating or bulk-changing more than 10 items in one go.
- Anything that compares named people.

## What a "yes" means

- A yes covers only the changes on the plan you were shown. It does not carry to
  the next run.
- If you edit the draft after approving it, the plan is shown again before
  writing.
- If some writes succeed and others fail, resume from the existing run receipt.
  Never repeat a succeeded action. Verify an external action with an uncertain
  outcome before retrying it; if it cannot be verified, ask the user.

## The first-month rule

For the first month of using any job that writes to other people's screens,
review every output before it goes. The habit is worth more than the speed.
